## Audit coverage and repair plan

Source review covers home/empty wallet, paper preview and transitions, swipe actions, import progress/error/manual fallback, camera/confirmation/permissions, full review/date/keyboard/source confirmation, focused comparison, original zoom/text, history/search/filter/match detail, split assignment/policies/save/finalize/summary, Settings/appearance/app lock, encrypted backup/Files and lock/background lifecycle. Fictional native scenarios verify the affected interactions without private data or normal-store changes.

| ID | Confirmed issue | Repair and acceptance |
| --- | --- | --- |
| UX01 | Entering Edit resets original-review flags even without an edit. | Restore saved review state; legacy reviewed receipts retain their verified status. Real field/evidence changes still require a fresh explicit confirmation, without making the user reopen an already-viewed original. Drafts never receive automatic approval. |
| UX02 | A reverse pan starts from zero and can expose the opposite action immediately. | Capture the current revealed offset; drag continuously from it. A gesture that starts with an action exposed is confined to that side and closes at center. A separate gesture can open the opposite side. Cancellation restores the prior settled state; disabled opposite actions cannot block closing. |
| UX03 | Unchanged saved-receipt editing still asks to discard changes. | Track the edit baseline. Cancel returns directly if nothing meaningful changed; changed drafts retain the discard prompt. Unfinished imports remain explicitly discardable. |
| UX04 | Full-wallet search normalization repeats when a receipt's original finishes loading or a star/split changes. | Cache wallet chronology on receipt changes, compare civil dates without formatting during sorting, avoid assigning unchanged records; update the memory index incrementally, reusing immutable text documents while refreshing current organization/split metadata. Compare results against a fresh index and measure large fictional collections. |
| UX05 | Original display orientation/rasterization runs synchronously on the UI thread; focused row changes recreate it. | Prepare an oriented, bounded display raster in a cancellable background task. ## Verification and limits

Preserve the established paper/leather/Liquid Glass design, exact money, source provenance, draft/Finish gates, device-bound storage/backup identities and local signing settings. Use a task-created iPhone 15 Pro Simulator and fictional data only. Record original failing reproductions separately from final tests, inspect light/dark/large-text screens, repeat home/history/original/review/split/camera/backup paths, and compile Release. UI automation and simulator timing do not prove zero hitches on physical hardware; Phase 3 phone smoothness remains an explicit follow-up.

Apple guidance informs the plan: [familiar gestures](https://developer.apple.com/design/human-interface-guidelines/gestures/), [keep non-UI work off the main thread](https://developer.apple.com/documentation/xcode/improving-app-responsiveness), and [avoid repeated expensive view work](https://developer.apple.com/documentation/xcode/understanding-and-improving-swiftui-performance).

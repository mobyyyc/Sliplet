# Phase 9 · Everyday receipt UX

**Proposed outcome.** When a receipt reads correctly, the owner can compare it with the original, confirm it, and put it in the wallet without opening an editor. When one line is wrong, correcting it should be a small detour that returns to the same place. A saved receipt should be easy to find by something the owner remembers buying.

**Starting evidence.** The owner reported a correct Gemini read on the iPhone 15 Pro. The current review view begins with “Check first” and renders purchase line editors inside a Form. Upload preview, local recognition, focused corrections, save-as-draft, wallet motion, item search, splits, Face ID and backup already exist. Phase 8 observed 18–45 second successful provider waits. These observations guide the audit. Current tap counts, correction time and frame performance need a fresh baseline.

| Task | Deliverable | Acceptance check |
| --- | --- | --- |
| P9-01 · Walk the app | Record a current-build Simulator walkthrough with fictional data. Trace a clean import, a one-line mistake, a failed read, a long receipt, a wallet return and an item search. Sample split, archive, settings, lock and backup for navigation consistency. Rank findings by impact, distinguish reproduced defects from preferences, and sketch the clean-review and correction screens. | Baseline taps, repeated actions, scroll resets and visible stalls. Separate provider wait from active interaction. Main reviews the two screen sketches before implementation. |
| P9-02 · Review a correct receipt | Present the familiar digital paper immediately after recognition. Merchant, date, item names and amounts, adjustments and totals use the saved receipt’s reading order. Put Original within reach and preserve reading position across comparison. Show one clear finish action plus Save draft. | A correct long receipt can be read, compared in full and saved with zero field-editor visits. Explicit original confirmation and exact reconciliation still govern Finish. Missing data and a default currency remain distinguishable from printed values. |
| P9-03 · Correct one thing | Tap a row or a flagged issue to edit its fields together. For example, correct a weighted item’s quantity or price and return to the same row. Use existing Apply/Cancel working copies. Keep unresolved items in context and explain what prevents finishing. | Apply changes only the intended fields. Cancel leaves the draft intact. An unresolved mismatch can be saved as a draft. Opening an already reviewed receipt and backing out preserves its review state. Test an actual content change separately. |
| P9-04 · Import and wait | Audit choices across camera, Photos and Files. Keep the exact cloud preview, covers and explicit Send action clear. Use truthful reading status and make recovery from a slow or failed read reachable with the existing photo. | Import has one home entry point. The user can identify what will leave the device, cancel a pending read, or continue locally where supported. Repeated taps cannot send twice. Validate success, timeout, offline and permission-denied states with fixtures. |
| P9-05 · Browse and retrieve | Polish the existing wallet pocket and paper stack, then carry the same paper into detail. Preserve stack height and layer order on return. Verify reverse swipe closes the open action first. Search opens with its short upward fade and returns to the same query and results. Check star, archive, restore and split entry. | Repeat open/back and swipe reversal with one, several and 30 receipts. Find a purchase by item name and return to results without retyping. Profile reproducible motion hitches on the same device/build conditions. |
| P9-06 · Personal beta | Apply shared action sizes, spacing, glass treatment, focus and VoiceOver labels across the flows above. Exercise light/dark paper, large text, Reduce Motion, long receipts, keyboard and bottom safe area. Ask the owner to repeat the baseline tasks on the iPhone. | Compare baseline and final taps, active time and observed motion on equivalent fixtures. Record device-only feedback separately. Resolve blockers for import, review, save and retrieval before calling the beta ready. |

Use the existing leather pocket, paper edges and layer shadows as the visual foundation. Reserve Liquid Glass for interactive controls and keep paper readable. Use a reachable primary action and native controls across screens. Prefer a clear reading hierarchy before adding gestures.

Main handles one approved task at a time, records the result and commit, and presents the next task for approval. This roadmap is design only. P9-01 is the proposed first task.
